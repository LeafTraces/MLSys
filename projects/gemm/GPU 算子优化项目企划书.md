# GPU 算子优化项目企划书

Nov 16, 2026 · @Kappipla

## 这个项目是什么

在自己的 RTX 5080 上，从零手写并逐步优化 GPU 矩阵乘法（GEMM）kernel，尽量逼近 NVIDIA 官方库 cuBLAS 的速度；然后用同一套技术写一个 FlashAttention 前向 kernel。全程用性能分析工具解释每一步为什么变快。

最终成果是一个 GitHub 仓库，里面有`四样`东西：

- 各个版本的 kernel 源码，从最朴素的写法到最终版本，每一版都保留
- 一套可复现的 benchmark，以及与 cuBLAS 对比的性能曲线
- roofline 图：标出每个版本受限于带宽还是算力
- 每一步优化的记录：先预测能快多少，再实测，再解释差距

## 为什么做这个

目标是学完 15-442 之后，有一个能写进简历、偏 MLSys 底层的个人项目。

- **否决的方案：** 普通的 LLM 推理引擎。它和 EECS498 里用 PyTorch 手写 Attention 区别不大，体现不出系统能力。
- **选定的方向：** GPU 算子优化。它直接用到课程最核心的内容（分块、数据复用、CUDA、Tensor Core、FlashAttention），结果可以用数字衡量，而且有一个公认的强对手（cuBLAS）作参照。
- **顺序：** 算子优化是主线；学有余力，再用自己写的 kernel 搭一个迷你推理引擎。

## 工作方式

项目在一个单独的对话里做，方式是 learn by doing：代码由你写，Claude 负责提示、检查和解释。

1. **先交思路，再写代码。** 沿用课上的五步法：标注类型和形状、手算最小例子、写注释骨架、逐行翻译、先预测再运行。
2. **先预测，再测量。** 每做一步优化前，先用课上的公式估计能快多少；测完对比，差距大就找原因。这些记录就是项目文档的主体。
3. **卡住再问。** Claude 先给提示，不直接给完整答案；同一个点试了三次还不对，才直接讲清楚。
4. **每次结束更新进度文件。** 在仓库里维护 `projects/PROGRESS.md`，记下做到哪一步、实测数字（标明是哪块显卡）、遗留问题和下一步。下次开新对话时把它附上，进度就能接上。

两个对话的分工：课程对话负责系统地讲 lecture；项目对话只讲当前这一步用得上的新知识。

项目代码建议放在仓库的 `projects/gemm/` 下，和现有的 `labs/`、`notes/` 并列。这个目录还没建，开工时再定。
