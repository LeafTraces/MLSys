GPU 架构与 CUDA 编程

Slides：06-CUDA-programming.pdf（69 页） 前置：Lec 5 分块与复用 · 61C SIMD / OpenMP

一句话：GPU 把 SIMD 推到极致：很多 ALU 共享一条指令流，再用大量线程轮流上场，把内存等待藏起来。CUDA 让你以 grid → block → thread 的层级一次启动成千上万个线程；硬件以 32 个线程（warp）为单位执行，以 block 为单位调度。写快的 kernel，本质上还是 Lec 5 那件事：让每个读进来的数被用很多次，再加上两条 GPU 特有的规矩：同一个 warp 走同一个分支，相邻线程访问相邻地址。

四个案例都在讲同一件事：朴素写法里同一个数被不同线程重复读；分块让它只读一次，把复用放进 shared memory 和寄存器。

PART 1CUDA 编程模型

从 SIMD 到 GPUp.2–4

61C 的 SSE 是一条指令处理 4 个 float。GPU 让几十个 ALU 共享一次取指和译码，把省下来的控制逻辑和大 cache 的面积都换成计算单元。

61C 学过的GPU
一条指令内SSE：4 路warp：32 路
多核之间OpenMP：8 个左右线程同时驻留几万个线程

线程层级：grid → block → threadp.7–10

一次 kernel 启动 = 一个 grid；grid 由若干 block 组成，每个 block 里有若干 thread。两级都可以是最多 3 维的，用 dim3 描述。slides 的例子是在 12 × 6 的矩阵上算 C = A + B：

dim3 threadsPerBlock(4, 3, 1);        // 每个 block 4 × 3 = 12 个线程
dim3 numBlocks(Nx/4, Ny/3, 1);        // (3, 2, 1)：6 个 block
matrixAdd<<<numBlocks, threadsPerBlock>>>(A, B, C);   // 共 72 个线程
每块颜色区域是一个 block，每个小方格是一个线程。x 对应列 i，y 对应行 j，所以代码写 C[j][i]。
__global__ void matrixAdd(float A[Ny][Nx], float B[Ny][Nx], float C[Ny][Nx]) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;   // 全局列号
    int j = blockIdx.y * blockDim.y + threadIdx.y;   // 全局行号
    C[j][i] = A[j][i] + B[j][i];
}
内置变量含义本例
gridDimgrid 有几个 block(3, 2, 1)
blockIdx我在第几个 block(0..2, 0..1)
blockDim每个 block 有几个线程(4, 3, 1)
threadIdx我在 block 内的位置(0..3, 0..2)

全局编号 = 第几个 block × 每个 block 的线程数 + block 内编号。和 Lec 5 的「块号 × 块大小 + 块内偏移」是同一个思路。

例：blockIdx = (2, 1)、threadIdx = (1, 2) → i = 2×4+1 = 9，j = 1×3+2 = 5，负责 C[5][9]。算完用形状自查：行号要在 0..5，列号要在 0..11。

越界保护p.12

线程数是启动时你自己定的，不会自动等于数据量。标准套路是「向上取整算 block 数 + kernel 里判断越界」：

int numBlocks = (N + 127) / 128;      // 不能写 N / 128：整数除法会向下取整
// kernel 内：
int i = blockIdx.x * blockDim.x + threadIdx.x;
if (i >= N) return;

N = 1000 时启动 8 个 block、1024 个线程，最后 24 个线程什么都不做。

条件分支与发散p.13–17

同一个 warp 的 32 个线程共享一条指令流。遇到 if 时，如果有的线程走 if、有的走 else，硬件只能把两个分支先后都执行一遍，不该走的线程被屏蔽、空等。代价是两个分支的时间之和。

分支条件（按 i 每 32 个一组）结果
if (i % 2 == 0)每个 warp 里都是一半一半，每个 warp 都发散，利用率减半
if (i < 512)512 是 32 的倍数，每个 warp 要么全走 if、要么全走 else，不发散
if (i < 500)只有包含 480..511 的那个 warp 发散

发散只发生在同一个 warp 内部；不同 warp 走不同分支没有代价。

PART 2GPU 硬件如何跑起几万个线程

出发点的矛盾：GTX 980 有 16 个 SM，每个 SM 每周期执行 4 × 32 个乘加，全芯片 2048 个 ALU；但每个 SM 能驻留 64 个 warp × 32 = 2048 个线程，全芯片 32768 个。线程数是 ALU 数的 16 倍，为什么要这么多线程待命？

warp：硬件真正调度的单位p.29–30、41

硬件以 32 个线程为一组取指和执行，这一组叫 warp。同一个 warp 永远执行同一条指令。发散的单位就是 warp；block 由若干 warp 组成（128 线程 = 4 个 warp），所以 block 线程数最好是 32 的倍数。

延迟隐藏：卡住就换人

访问显存要几百个周期。CPU 用大 cache 和乱序执行，尽量别让线程卡住；GPU 的做法是：一个 warp 在等数据时，调度器立刻切到另一个数据已经到位的 warp。

单看任何一个 warp，它 75% 的时间都在等；但最下面一行 ALU 一个周期都没空。多出来的线程是用来轮流填补等待的。

切换几乎免费：所有驻留 warp 的寄存器同时放在 SM 巨大的寄存器堆里，不用像操作系统那样保存、恢复。

每个调度器需要的 warp 数 ≈ 1 + L / c　　（c = 每次算几个周期，L = 每次等几个周期）

注意是每个调度器。一个 SM 有 4 个调度器，所以 c = 10、L = 200 时，每个调度器需要 21 个 warp；一个 SM 驻留 16 个 warp，平摊下来每个调度器只有 4 个，远远不够。这种「算得少、等得久」的 kernel，光靠提高占用率救不回来，必须减少访存。

代价：资源决定能驻留多少 warpp.27–28、31–36

每个驻留的 block 会一直占着三种资源：执行上下文（每 SM 最多 64 个 warp）、寄存器（每线程用量 × 线程数）、shared memory。能驻留的 block 数 = 三者各自能容纳的最小值。驻留 warp 数 ÷ 上限 = 占用率。

slides 的动画假设一个 SM 只有 1.5 KB shared memory，卷积 block 每个要 130 × 4 = 520 B：放 2 个用 1040 B，第 3 个要 1560 B > 1536 B，放不下。（slides 从第 32 页起把 520 B 写成了 512 B，是笔误。）

例：96 KB shared、最多 64 warp，block 256 线程驻留 blockwarp占用率
每个 block 40 KB shared⌊96/40⌋ = 21616/64 = 25%
每个 block 24 KB shared43232/64 = 50%

想要更多复用（更大的分块），就要更多 shared memory 和寄存器；想要更好的延迟隐藏，每个 block 占的资源就得少。两者互相拉扯，调 GEMM 的分块大小就是在找平衡点。

block 调度：为什么 block 之间不能互相等待p.26、28、32–40

调度器把 block 动态地分到资源足够的 SM 上，谁结束就补谁，执行顺序无法预测。CUDA 约定 block 之间不能有依赖，换来两个好处：同一份程序能在 6 个 SM 和 132 个 SM 的卡上运行；不会死锁。

反例：GPU 只能同时驻留 16 个 block，你启动 100 个。如果这 16 个驻留位置都被「自旋等待后面某个 block」的 block 占着，它们永远不会结束、永远不释放位置，它们等的 block 就永远上不来。硬件不保证顺序，也不抢占，所以干脆禁止。

先判断瓶颈：算术强度

PART 4案例二：并行归约

求和、求最大值在 softmax 和 LayerNorm 里每层都要用。GPU 用树形归约：每轮两两相加，log₂n 轮剩一个。

跨 block：拆成多次 kernel 启动p.56–58

block 之间不能等待，所以每次启动让每个 block 写出一个部分和，再对部分和启动下一次。kernel 结束就是全局屏障，启动开销很小。例：n = 2²⁰、256 线程/block → 4096 个 block → 16 个 → 1 个，共 3 次启动；最后一次只有 16 个数，靠越界判断处理多余线程。

bank 冲突

shared memory 分成 32 个 bank，第 i 个 4 字节字在 bank i mod 32。一个 bank 每周期只服务一个地址：warp 的 32 个线程访问 32 个不同 bank，一次完成；k 个线程访问同一 bank 的不同地址，就要排队 k 次，叫 k 路冲突（同一个地址会广播，不算冲突）。冲突路数 = 被访问最多的那个 bank 的线程数。

例：V2 第 1 轮，t0–t31 访问 sdata[2t]，bank(t) = 2t mod 32。t 与 t+16 撞在同一个 bank（0 ≤ t < 16），16 个偶数 bank 各被 2 个线程访问，奇数 bank 空闲 → 2 路冲突。

两个 __syncthreads()（p.60 的问题）

  • 装入之后：保证所有线程都把 global 的数写进 sdata，否则归约时会读到还没装好的位置。
  • 循环每一轮：下一轮要读上一轮别的线程写的结果。V3 中 s = 128 时 t64 执行 sdata[64] += sdata[192]；s = 64 时 t0 读 sdata[64]。没有屏障，t0 可能在 t64 写完之前读到旧值，漏掉 sdata[192]。

SELF-TEST自测题

Q1. N = 3000，每 block 256 线程。启动几个 block？多少线程空闲？

(3000 + 255) / 256 = 12 个 block，3072 个线程，72 个空闲。

Q2. dim3(8, 4) 的 block，blockIdx = (1, 2)、threadIdx = (5, 3) 负责 C 的哪个元素？

i = 1×8+5 = 13，j = 2×4+3 = 11，C[11][13]。

Q3. if (threadIdx.x < 48) … else …，block 128 线程，几个 warp 发散？

warp 1（t32–t63）里 t32–t47 走 if、t48–t63 走 else，只有这 1 个发散。

1/32；2N³ ÷ (2N³/32 × 4 B) = 8 FLOP/byte。

Q7. 协作搬运 L = 32、S = 16、nthreads = 128，几轮？tid = 40 每轮搬哪？

512/128 = 4 轮；idx = 40、168、296、424 → (1, 8)、(5, 8)、(9, 8)、(13, 8)。

Q8. 32 个 bank，warp 访问 sdata[4t]（t = 0..31），几路冲突？

bank = 4t mod 32，只用到 8 个 bank，每个 4 个线程 → 4 路冲突。

Q9. 为什么 V3 的循环是 s 从大到小，而不是从小到大？

s 从大到小时，t 访问 sdata[t] 和 sdata[t+s]，干活的线程编号连续、地址连续：既不发散也无 bank 冲突。

Q10. n = 2²⁴、每 block 512 线程，归约要启动几次 kernel？

2²⁴ → 2¹⁵ → 2⁶ → 1，共 3 次。
