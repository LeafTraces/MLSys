硬件加速：从 stride 到分块

Slides：05-hardware-acceleration.pdf 对应 61C：Lab 7 分块 · Lab 9 SIMD · Lab 10 OpenMP · Project 4

一句话：计算图里每个节点的 compute 最终都是一个 kernel。让它变快有三板斧：向量化、数据布局、并行化。以矩阵乘法为例，计算先当作免费，真正的成本是访存。寄存器分块和 cache 分块各减少一层的读取量，本质都是数据复用。

某个访问不依赖某个循环变量，就能沿这个循环被复用。分块，就是把这种复用框在快的存储层里。

PART 1通用加速技巧

向量化p.7

两个长度 256 的 float 数组相加：128 位向量指令一次处理 4 个 float，循环从 256 次变成 64 次。A、B、C 需要按 16 字节对齐，这就是 61C 里 _mm_load_ps（要求对齐）和 _mm_loadu_ps（不要求）的区别。

深色是一条指令处理的元素。向量化后，每 4 个元素只需一次加载、一次加法、一次存储。

stride 的代价：cache line 被浪费

1024×1024 float32 矩阵，读 16 个元素。一条 cache line 是 64 字节 = 16 个 float32。

沿 A 的一行：间隔 4 字节，连续
1 条 cache line · 利用率 16/16 = 100%
沿 A.T 的一行：间隔 1024×4 = 4096 字节 > 64
每个元素各占一条 → 16 条 · 利用率 4/64 = 1/16
蓝色是用到的数据，浅红是读进来但没用的。中间被跳过的 cache line 根本没读，不计入。利用率的分母永远是 64 字节，和矩阵大小无关。

两个代价：向量化困难（向量加载要求连续）+ cache 利用率低。解决办法是计算前 compact（np.ascontiguousarray / .contiguous()）。权衡：视图便宜，后续计算可能变慢；何时 compact 是 ML 编译器的决策之一。

并行化p.10

#pragma omp parallel for 把循环迭代分给多个线程（61C Lab 10）。三者关系：向量化是一个核内一条指令多个数据，并行化是多个核同时算，数据布局决定前两者能否发挥作用。

PART 2矩阵乘法案例

slides 计算 C = A · Bᵀ，即 C[i][j] = Σk A[i][k] · B[j][k]。A 和 B 都沿 k 方向、也就是按行读，在行主序下都是连续的。

成本模型p.13–14

计算先当作免费，只统计「从哪一层读了多少数据」，这就是 roofline 分析的雏形。朴素三重循环中，最内层执行 n³ 次，每次从 DRAM 读两个元素：

朴素成本 = 2 · dram · n³
两层分块各管一层存储。DRAM 比 L1 慢约 400 倍，所以减少最上面那根箭头的流量最值钱。

寄存器分块p.15–16

把 C 切成 v1×v2 的小块，整块在寄存器里算完再写回：

for i in range(n/v1):
  for j in range(n/v2):
    c[v1][v2] = 0              # 寄存器，k 循环前定义，一直复用
    for k in range(n/v3):
      a = A[i, k]              # v1×v3 → 寄存器
      b = B[j, k]              # v2×v3 → 寄存器
      c += a · bᵀ
    C[i, j] = c                # 每个 C 元素只写回一次

推导方法：读取总量 = 执行次数 × 每次读取量

L_A = (n/v1)(n/v2)(n/v3) · v1·v3 = n³/v2
L_B = (n/v1)(n/v2)(n/v3) · v2·v3 = n³/v1
A 的每个元素和 B 的 v2 个元素各乘一次，被复用了 v2 次，所以 A 的读取量降为 1/v2。同理 B 被复用 v1 次。C 小块常驻寄存器。

寄存器代价是 v1·v3 + v2·v3 + v1·v2。v3 没有出现在读取成本里，只会多占寄存器，所以令 v3 = 1。下面的计算器里可以自己拖动试一试：

寄存器 = v1·v2 + v1 + v2 = 15 / 16 ✓ 放得下
读取量 = n³/v1 + n³/v2 = 0.667 n³
相比朴素 2n³，减少到 33%

为什么方形最好

(v1, v2)寄存器≤ 16读取量
(1, 7)15✅1.14 n³
(2, 4)14✅0.75 n³
(3, 3)15✅0.67 n³
(2, 5)17❌—

读取量 = n³ · (v1+v2) / (v1·v2)。分子是 A、B 小块占的寄存器，分母是 C 小块的面积，也就是复用的来源。v1+v2 固定时，v1 = v2 乘积最大（均值不等式）。约束 (v1+1)(v2+1) ≤ 17 的边界是双曲线，不是圆。GPU GEMM 中每个线程的小块通常是 4×4、8×8，原因就在这里。

Cache 分块p.17–18

for i in range(n/b1):
  a = A[i]            # b1 × n，DRAM → L1（只在外层）
  for j in range(n/b2):
    b = B[j]          # b2 × n，DRAM → L1（随 i 重复读）
    C[i, j] = dot(a, bᵀ)   # 内部用寄存器分块
内层再用寄存器分块计算，所以还要求 b1 % v1 == 0、b2 % v2 == 0。
L_A = (n/b1) · b1·n = n²
L_B = (n/b1)(n/b2) · b2·n = n³/b1

A 的一块读进来后，被内层所有 j 复用，所以总共只读一遍；B 每换一个 i 就要重新读一遍。

合并成本p.19

dram · (n² + n³/b1) + l1 · (n³/v2 + n³/v1)

核心思想：数据复用p.20–22

访问不依赖沿哪个循环复用在代码里体现为
A[i][k]jj 循环A 小块 / A 块被所有 j 共用
B[j][k]ii 循环B 小块被 v1 行 A 共用
C[i][j]kk 循环累加器 c 在 k 循环外定义

卷积同理：权重不依赖 batch 和输出空间位置 (h, w)，可以沿这些循环复用；一个输入像素被多个滑动窗口共用。

REVIEW易错点

错误正确做法
要「元素」单位却给了字节；把 float64 的 8 字节套到 float32先看单位，再看 dtype：float32 = 4 字节
只写公式不代数偏移、成本都要算出具体数字
说「隔 strides[1] 个元素」不说是谁的A.strides[1] = 1，A.T.strides[1] = 4，结论完全相反
把小例子的步长套到大矩阵上题目换了 n，步长要重算
用「间隔 ÷ 64」算 cache line 数间隔 ≥ 64 字节时，每个元素各占一条：读 k 个就是 k 条
利用率算出来和 n 有关利用率 = 用到的字节 / 64
「方形最优」用圆来类比边界是双曲线 (v1+1)(v2+1) ≤ 17；用均值不等式解释

SELF-TEST自测题

Q1. 5×8 float32 行主序矩阵，以字节为单位，A 和 A.T 的 strides？A[3][2] 的元素偏移？

元素：A (8, 1)，A.T (1, 8)。字节：A (32, 4)，A.T (4, 32)。偏移 = 3·8 + 2·1 = 26。

Q2. 把 (4,) 的向量广播到 (3, 4)，strides（元素单位）？为什么只读？

(0, 1)。三行指向同一块内存，写入会因别名同时改动多行和原数组。

Q3. 2048×2048 float32，沿 A.T 的一行读 32 个元素，读几条 cache line？利用率？

间隔 8192 字节 > 64，每个元素各占一条：32 条，利用率 4/64 = 1/16。

Q4. 寄存器分块中为什么 v3 取 1？

L_A = n³/v2、L_B = n³/v1，v3 被约掉，却增加 v1v3 + v2v3 个寄存器。

Q5. 64 个寄存器（v3 = 1），比较 (7, 7) 和 (4, 12)。

(7,7)：63 ✅，2/7 ≈ 0.286 n³。(4,12)：64 ✅，1/4+1/12 ≈ 0.333 n³。方形更优。可以用上面的计算器验证。

Q6. Cache 分块中交换 i、j 循环（B 放外层），读取量变成什么？

L_B = n²，L_A = n³/b2。复用对象换成 B，代价转到 A 上。

Q7. 为什么 slides 计算 A·Bᵀ 而不是 A·B？

A、B 都沿 k 方向（行内）读，行主序下连续；A·B 的 B 要按列读，步长为 n。

Q8. 卷积 out[n][co][h][w] += in[n][ci][h+kh][w+kw] · W[co][ci][kh][kw]，W 可沿哪些循环复用？

W 不依赖 n、h、w，可沿 batch 和输出空间位置复用。
